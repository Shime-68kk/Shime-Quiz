# Deployment Guide — ShimeChamhoc v2.0.0-beta-ai.1

ShimeChamhoc v2 is a React/Vite static app. It does not require an app-owned API, database, account system, or server runtime for core learning flows.

> v2 staging/beta deployment details live in [`DEPLOY_V2.md`](DEPLOY_V2.md). Keep this file as the short deployment guide and use `DEPLOY_V2.md` for platform-specific beta validation.


## Build output

For production, build the Vite app and deploy the generated `dist/` directory:

```bash
npm install
npm run build
```

Local production preview:

```bash
npm run preview
```

Open:

```text
http://127.0.0.1:4173
```

## Required runtime behavior

The deployed app should support:

- `/dashboard`
- `/library`
- `/study-room`
- static JS/CSS assets generated by Vite
- local JSON/CSV import in the browser
- localStorage-backed v2 learning data
- local full/redacted/progress-only backup export

## Base path safety

Vite uses `import.meta.env.BASE_URL` and React Router uses that base path. Root deployments and subpath deployments are supported when the hosting platform serves `index.html` as the fallback for client-side routes.

Examples:

- root: `https://example.com/`
- subpath: `https://username.github.io/quiz-for-ptit/`

For GitHub Pages subpaths, set the Vite `base` option if your deployment process requires a fixed repository path.

## GitHub Pages

3. Ensure direct links such as `/dashboard` and `/library` route back to `index.html`.

## Optional external API note

Core v2 learning features are static/local-first. If a future or legacy AI explanation feature is present, it may call an external endpoint such as `https://quizct11.onrender.com/api/explain`. That endpoint is optional and can be unavailable without breaking library, Study Room, history, review, backup/restore, or local analytics flows.

## Local security note

The app stores data locally in the browser. Full backups are plaintext JSON and may include questions, correct answers, explanations, and study history. Redacted and progress-only exports reduce sharing risk but are not encryption. True answer-key protection requires future backend/server-side scoring.

## Rollback instructions

1. Redeploy the previous known-good static artifact.
2. Ask testers to hard reload once.
3. If browser data appears stale, clear site data for the staging origin.
4. Re-run the v2 smoke checklist.

## Staging smoke checklist

Use a clean browser profile or clear site data first.

1. Load the staging URL.
2. Confirm `/dashboard`, `/library`, and `/study-room` render.
3. Import valid JSON and CSV files.
4. Reload and confirm library persistence.
5. Complete one Study Room session.
6. Confirm history, analytics, mastery, review schedule, and Today Journey update.
7. Export full, redacted, and progress-only backups.
8. Restore a full backup.
9. Confirm redacted/progress-only restore is blocked with Vietnamese explanations.
10. Check mobile width and keyboard navigation.
