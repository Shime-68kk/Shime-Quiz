## Purpose

Phase 28A is a planning/design gate for generated/test restore rehearsal design. It establishes the scope, constraints, and approach for a future rehearsal of restore flows using generated/test data — not real learner data.

Phase 28A is a separate planning/design gate and is not automatically approved.

This seed does not implement Phase 28A. It only defines the planning inputs and candidate directions for consideration.

## Planning constraints

The following constraints apply to Phase 28A planning:

1. **Generated/test data only**: No real learner data may be used in restore rehearsal. All rehearsal inputs must be synthetically generated by the test harness.

2. **No backup file format changes**: Phase 28A planning must not propose backup file format changes. Any format change requires a separate design gate.

3. **No restore overwrite behavior changes**: Phase 28A planning must not propose changes to how restore overwrites existing data. Any such change requires a separate safety review.

4. **No production restore rehearsal by default**: Production restore rehearsal is not automatically approved. A separate safety gate is required before any production restore rehearsal.

5. **No real learner data restore rehearsal**: Restore rehearsal using real learner data is not approved by this seed or by Phase 28A planning.

6. **No storage migration**: Phase 28A planning must not propose storage migration.

7. **No production adapter-aware backup/export/restore**: Production integration of adapter-awareness into backup/export/restore flows is not approved by Phase 28A planning.

8. **No automatic backup**: Phase 28A planning must not propose automatic backup behavior.

9. **No platform backup preservation claims**: Phase 28A planning must not claim platform backup preservation without a separate safety gate.

10. **No guaranteed data-loss prevention claims**: Phase 28A planning must not claim guaranteed data-loss prevention.

11. **No sync/cloud/account/auth/backend**: Phase 28A planning must not propose sync, cloud, account, authentication, or backend changes.

12. **No telemetry/analytics**: Phase 28A planning must not propose telemetry or analytics changes.

13. **No BETA_READY**: Phase 28A does not claim BETA_READY.

14. **No local-first hybrid readiness**: Phase 28A does not claim local-first hybrid readiness.

## Candidate directions

The following directions are candidates for Phase 28A consideration:

1. **generated/test restore rehearsal design**: Design a restore rehearsal framework using synthetically generated backup data. Define what a generated/test restore rehearsal looks like, what evidence it produces, and what claims it may support. This is the recommended direction.

2. **manual/browser evidence matrix for generated/test restore rehearsal**: Design a matrix of manual/browser evidence scenarios that would be needed before any generated/test restore rehearsal could be promoted to browser evidence. Define evidence collection protocol.

3. **adapter-awareness prototype rollback or keep decision**: Decide whether to keep or remove the Phase 27E prototype based on evidence gathered during Phase 28A planning. Define criteria for the keep/remove decision.

4. **backup/export/restore adapter-awareness production design exploration**: Explore what production-level integration of adapter-awareness into backup/export/restore flows would require. This is a design exploration only, not implementation approval.

5. **local-first hybrid readiness re-decision**: Re-evaluate the local-first hybrid readiness decision in light of Phase 27 evidence. This requires additional evidence beyond Phase 27F.

## Required gates before runtime

Before any generated/test restore rehearsal reaches runtime/production:

1. Phase 28A design gate must be completed
2. A separate evidence collection protocol must be established
3. Generated/test data must be validated as not derived from real learner data
4. A separate safety review for any restore behavior changes
5. Manual/browser evidence collection (not unit/static) for any browser behavior claims
6. A separate production integration gate (not Phase 28A)
