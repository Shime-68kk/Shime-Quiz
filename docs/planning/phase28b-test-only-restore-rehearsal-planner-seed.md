## Purpose

Phase 28B is the next planned gate after Phase 28A. This seed defines the planning inputs, constraints, and candidate directions for Phase 28B consideration.

Phase 28B is a separate test-only/no-write implementation gate and is not automatically approved. This seed does not implement Phase 28B. It only defines the planning inputs and candidate structures for future consideration.

Phase 28B may implement a test-only/no-write restore rehearsal planner if all required gates defined in the Phase 28A run pack pass.

## Planning constraints

The following constraints apply to Phase 28B planning and implementation:

1. **Generated/test data only**: No real learner data may be used. All planner inputs must be synthetically generated by the test harness.

2. **No production state writes**: The planner must be a pure function. It must not call `localStorage.setItem`, `localStorage.removeItem`, `localStorage.clear`, or any IndexedDB write transaction.

3. **No production restore path calls**: The planner must not call the production restore import function.

4. **No backup file format changes**: Phase 28B must not change the backup file format.

5. **No restore overwrite behavior changes**: Phase 28B must not change how restore overwrites existing data.

6. **No production imports**: No production module may import the Phase 28B planner.

7. **No storage driver changes**: Phase 28B must not change the default localStorage driver or IndexedDB driver.

8. **No storage migration**: Phase 28B must not propose storage migration.

9. **No production adapter-aware backup/export/restore**: Production integration of adapter-awareness is not approved in Phase 28B.

10. **No sync/cloud/account/auth/backend**: Phase 28B must not add sync, cloud, account, authentication, or backend changes.

11. **No telemetry/analytics**: Phase 28B must not add telemetry or analytics.

12. **No BETA_READY**: Phase 28B does not claim BETA_READY.

13. **No local-first hybrid readiness**: Phase 28B does not claim local-first hybrid readiness.

14. **No browser/manual evidence**: Phase 28B is a test-only/unit-evidence gate. Browser/manual evidence requires a separate phase.

15. **Test files only for planner**: The restore rehearsal planner must live in a test-only directory or be explicitly gated so that no production module imports it.

## Candidate planner functions

The following candidate function names are for Phase 28B design consideration only. They are not implemented in Phase 28A.

```text
normalizeRestoreRehearsalPlanInput
createGeneratedTestRestoreRehearsalPlan
deriveRestoreRehearsalSafetyState
summarizeRestoreRehearsalPlan
```

**`normalizeRestoreRehearsalPlanInput`**
Purpose: Validate and normalize a synthetic backup fixture input for restore rehearsal planning.
Inputs: Raw synthetic backup fixture object.
Outputs: Normalized plan input or validation error.
Constraints: Must reject any input that does not conform to the expected backup structure. Must not access real storage.

**`createGeneratedTestRestoreRehearsalPlan`**
Purpose: Create a restore rehearsal plan from a normalized synthetic fixture input.
Inputs: Normalized plan input from `normalizeRestoreRehearsalPlanInput`.
Outputs: A plan object describing what a restore would entail — no writes executed.
Constraints: Pure function. No side effects. No storage writes. No production restore path calls.

**`deriveRestoreRehearsalSafetyState`**
Purpose: Derive a safety state summary for a restore rehearsal plan, using adapter-awareness signals if available.
Inputs: Restore rehearsal plan; optional adapter-awareness state from Phase 27C model.
Outputs: Safety state object including: `canClaimProductionSafety` (always false for test-only), `generatedTestDataConfirmed`, `noWritesConfirmed`, `safetyFlags`.
Constraints: Must always return `canClaimProductionSafety: false`. Must not execute writes. Must not import production backup/restore modules.

**`summarizeRestoreRehearsalPlan`**
Purpose: Produce a human-readable summary of the restore rehearsal plan and safety state for test output.
Inputs: Restore rehearsal plan; safety state.
Outputs: Summary string or object for test assertion.
Constraints: Pure function. No side effects. No storage writes.
